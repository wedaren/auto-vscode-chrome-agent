## 案例 1：基础对话 — 与 AI 在浏览器中智能聊天

### 场景描述

你正在浏览 GitHub 上一个开源项目的 README 页面，想快速了解项目的核心架构和技术选型，而不是逐字阅读长文档。

### 前置条件

- VSCode 插件已启动（WebSocket 服务运行中）
- Chrome 插件已安装，Side Panel 状态指示灯为绿色 🟢

### 操作步骤

1. **打开目标页面** — 在 Chrome 中打开 GitHub 项目的 README 页面。

2. **打开 Side Panel** — 点击 Chrome 工具栏中的 Browser Agent 图标，打开侧边栏。

3. **选择模型** — 在顶部模型选择下拉框中选择 `GPT-4o` 或 `Claude 3.5 Sonnet`。

4. **使用快捷按钮** — 欢迎界面显示 4 个快捷按钮，点击 🔍 **探索此页面**。

5. **查看回复** — AI 会自动获取当前页面的 URL 和标题作为上下文，返回该项目的关键信息摘要，以 Markdown 格式渲染（包含代码块、列表等）。

6. **追问细节** — 在输入框中输入追问，如：
   ```
   这个项目用了哪些设计模式？有什么值得学习的地方？
   ```
   按 **Enter** 发送。

7. **选中关键段落追问** — 用鼠标选中页面上的一段代码或文字，上下文指示条会显示"已选中 XXX 字"。然后在 Side Panel 中输入：
   ```
   帮我解释一下选中的这段代码
   ```
   AI 会基于选中内容精准回答。

8. **复制有用内容** — 鼠标悬停在 AI 回复的代码块上，点击复制按钮一键复制。

### 预期结果

- AI 能准确感知当前页面上下文，回复紧密结合页面内容
- Markdown 渲染效果良好：代码高亮、表格对齐、列表层级清晰
- 选中文本后追问，AI 精准定位到选中内容进行回答
- 整个对话流畅，响应为流式输出，无需等待全部生成完毕

### 技巧

- 按 **↑**（输入框为空时）可快速回溯上一条消息并修改重发
- 使用 **Shift+Enter** 可以换行输入多行问题
- 点击 AI 回复旁的**重新生成**按钮可获取不同角度的回答

## 案例 2：浏览器自动操作 — 让 Agent 替你操作网页

### 场景描述

你需要在一个电商网站上搜索商品并比较价格，但不想手动逐个操作。你希望 Agent 自动帮你完成搜索、滚动、提取信息等一系列浏览器操作。

### 前置条件

- VSCode 插件已启动，Chrome 插件已连接（绿色指示灯 🟢）
- Agent 模式已自动激活（Chrome 插件连接后，原生浏览器工具可用）
- 在 VSCode Activity Bar 的 Browser Agent 面板中，**Native Browser Tools** 节点为绿色 ✅

### 操作步骤

1. **打开目标网站** — 在 Chrome 中打开电商网站首页。

2. **下达操作指令** — 在 Side Panel 输入：
   ```
   帮我在搜索框中搜索"机械键盘"，然后滚动页面查看前5个商品的名称和价格
   ```

3. **观察 Agent 执行过程** — Agent 进入 ReAct 循环，Side Panel 中会实时展示步骤：

   - 🧠 **Think**：分析页面结构，需要先找到搜索框
   - ⚡ **Act** `[browser_click]`：点击搜索输入框 `selector: "input[name='search']"`
   - 📋 **Observe**：点击成功
   - ⚡ **Act** `[browser_type]`：输入搜索关键词 `value: "机械键盘"`
   - 📋 **Observe**：输入完成
   - ⚡ **Act** `[browser_click]`：点击搜索按钮 `selector: ".search-btn"`
   - 📋 **Observe**：搜索结果页已加载
   - ⚡ **Act** `[browser_scroll]`：向下滚动查看更多商品 `mode: "by-pixels", pixels: 500`
   - ⚡ **Act** `[browser_get_text]`：获取商品列表的文本内容
   - 📋 **Observe**：提取到商品数据
   - 🧠 **Think**：已获取足够信息，整理结果

4. **获取最终回答** — Agent 汇总所有观察结果，返回结构化的商品对比信息。

5. **继续追加操作** — 你可以进一步指示：
   ```
   帮我点击第一个商品，查看它的详细规格参数
   ```

### 预期结果

- Agent 自动拆解复杂任务为多个 `browser_click`、`browser_type`、`browser_scroll`、`browser_get_text` 等工具调用
- 每个步骤实时展示在 Side Panel 中，透明可追踪
- 最终结果汇总为清晰的文本回答
- 默认只展开最近 3 步，点击"展开 N 个更早的步骤…"可查看完整执行过程

### 可用的浏览器操作工具

| 工具 | 用途 | 示例 |
|------|------|------|
| `browser_click` | 点击元素 | 点击按钮、链接、菜单项 |
| `browser_type` | 输入文字 | 填写表单、搜索框 |
| `browser_navigate` | 跳转 URL | 打开新页面 |
| `browser_scroll` | 滚动页面 | 向下翻页、滚动到指定元素 |
| `browser_screenshot` | 截取页面 | 记录页面当前状态 |
| `browser_query_selector` | 查询元素属性 | 获取元素的标签、类名、ID |
| `browser_get_text` | 获取文本 | 提取页面文字内容 |
| `browser_get_attribute` | 获取属性值 | 读取 href、src 等属性 |
| `browser_wait` | 等待元素出现 | 等待异步加载完成 |
| `browser_highlight` | 高亮元素 | 可视化标记目标元素 |

### 技巧

- 尽量描述清楚你想操作的元素特征（如"搜索框"、"登录按钮"），Agent 会自动推断 CSS 选择器
- 如果 Agent 操作方向错误，随时点击 **停止按钮** 中断执行
- 操作完成后可以用自然语言追问，Agent 会基于之前的操作结果继续

## 案例 3：深度报告 — 生成结构化分析报告

### 场景描述

你正在做竞品分析，需要基于当前浏览的竞品官网页面生成一份结构化的分析报告，包括产品定位、核心功能、技术架构、优劣势等维度。

### 前置条件

- VSCode 插件已启动，Chrome 插件已连接
- 已打开目标竞品网站

### 方式一：通过 Chrome Side Panel 生成报告

#### 操作步骤

1. **打开竞品网站** — 在 Chrome 中浏览竞品的产品页面、文档页面等。

2. **使用快捷按钮** — 在 Side Panel 欢迎界面点击 📝 **生成报告**。

   或者直接输入更具体的指令：
   ```
   帮我分析这个产品页面，生成一份结构化的竞品分析报告，包含以下维度：
   1. 产品定位与目标用户
   2. 核心功能列表
   3. 技术架构特点
   4. 优势与劣势分析
   5. 与我们产品的差异对比
   ```

3. **查看报告** — AI 基于页面上下文（URL、标题、页面内容）生成完整的报告，以 Markdown 格式渲染在 Side Panel 中。

4. **复制报告** — 鼠标悬停在 AI 回复上，点击**复制按钮**将报告内容复制到剪贴板，粘贴到文档工具中进一步编辑。

### 方式二：通过 VSCode 命令面板生成报告

#### 操作步骤

1. **确保 Chrome 已连接** — Side Panel 状态指示灯为绿色。

2. **执行命令** — 在 VSCode 中按 `Cmd+Shift+P`（Mac）/ `Ctrl+Shift+P`（Windows），输入：
   ```
   Browser Agent: 生成报告
   ```

3. **输入报告主题** — 在弹出的输入框中输入主题，如：
   ```
   当前页面的用户体验分析与改进建议
   ```

4. **查看报告输出** — 报告将输出到 VSCode 的 Output Channel。打开方式：**查看 → 输出**，在下拉列表中选择 **Browser Agent**。

### 预期结果

- 报告结构化清晰，包含标题、章节、列表、表格等 Markdown 元素
- 报告内容紧密结合当前浏览页面的实际信息
- 两种生成方式都可用，Chrome 端更直观，VSCode 端适合深度编辑

### 技巧

- 在发起报告前先**选中页面上的核心段落**，AI 会将其作为重点分析对象
- 可以在同一会话中持续追问，迭代优化报告内容，如"请补充技术栈分析部分"
- 切换到竞品的不同子页面，发起新报告或追问，积累多角度信息

## 案例 4：调试排查 — 利用调试视图定位问题

### 场景描述

你在使用 Browser Agent 时发现 Agent 的浏览器操作执行了但结果不符合预期——比如 Agent 点击了错误的按钮，或者工具返回了意料之外的结果。你需要排查问题原因。

### 前置条件

- VSCode 插件已启动，Chrome 插件已连接
- 已执行过一次或多次 Agent 对话

### 操作步骤

1. **打开调试面板** — 在 VSCode 左侧 Activity Bar 中点击 **Browser Agent 图标**，展开调试面板。面板包含三个视图：

   - **连接状态**（Connection Status）
   - **消息检查器**（Message Inspector）
   - **Agent 循环可视化**（Agent Loop）

2. **检查连接状态** — 在"连接状态"视图中确认所有组件正常：

   | 节点 | 正常状态 |
   |------|----------|
   | WebSocket Server | ✅ 监听中，端口 7777 |
   | MCP Connection | ✅ 已连接（如果已连接 MCP） |
   | Native Browser Tools | ✅ 可用 (10 tools) |
   | Current Model | 已选中模型名称 |

   > 如果某个节点显示 ❌，说明该组件未正常运行，是问题的潜在原因。

3. **查看 Agent 循环步骤** — 在"Agent 循环可视化"视图中，找到最近的运行记录：

   ```
   ❌ [14:28:00] Error (3 steps) — 帮我点击页面上的登录按钮...
   ```

   展开该记录，逐步查看 ReAct 步骤：

   ```
   🧠 #1 Think  分析页面结构，需要找到登录按钮...
   ⚡ #2 Act [browser_click]  {"selector":"#login-btn"}
   📋 #3 Observe  {"success":false,"error":"Element not found"}
   ```

   **鼠标悬停**在步骤上，Tooltip 会显示完整内容（最多 1000 字符），包括 Act 步骤的工具名和完整参数 JSON。

4. **检查原始消息** — 在"消息检查器"视图中，查看 WebSocket 通信的原始数据：

   ```
   ↑ tool_execute [14:28:01.234] {"action":"click","selector":"#lo...
   ↓ tool_result  [14:28:01.456] {"success":false,"error":"Eleme...
   ```

   **点击消息条目**，会在编辑器中打开完整的消息 JSON：

   ```json
   // Direction: send
   // Timestamp: 2026-03-21T14:28:01.234Z
   // MessageId: 15

   {
     "type": "tool_execute",
     "payload": {
       "action": "click",
       "selector": "#login-btn"
     },
     "sessionId": "abc-123"
   }
   ```

5. **查看 VSCode 输出日志** — 打开 **查看 → 输出**，选择 **Browser Agent** 通道，查看详细的运行日志：

   ```
   [WsServer] 消息发送: tool_execute
   [BrowserToolProvider] 执行工具: browser_click, 参数: {"selector":"#login-btn"}
   [AgentLoop] 工具执行失败: Element not found
   ```

   日志按组件分类（`[WsServer]`、`[BrowserToolProvider]`、`[AgentLoop]`、`[McpClient]`、`[LmService]`），方便定位问题所在层级。

6. **定位根因** — 根据上述信息判断问题：
   - **选择器错误**：页面上没有 `#login-btn` 这个元素，可能是 Agent 推断的选择器不对
   - **解决方法**：在 Chrome 中右键检查目标元素，获取正确的选择器，然后指示 Agent 使用正确的选择器重试

7. **清理消息日志** — 排查完毕后，可以执行命令 `Browser Agent: Clear Message Log` 清空消息检查器，为下次调试准备干净的环境。

### 调试视图速查

| 视图 | 用途 | 数据量限制 |
|------|------|------------|
| 连接状态 | 确认各组件是否正常运行 | 4 个顶级节点，实时刷新 |
| 消息检查器 | 查看 WebSocket 原始通信数据 | 最多 200 条，最新在前 |
| Agent 循环 | 查看 Agent 的思考 → 工具调用 → 结果过程 | 最多 20 次运行记录 |

### 预期结果

- 通过 Agent 循环视图精确定位到是哪一步出了问题
- 通过消息检查器查看工具调用的原始参数和返回值
- 通过连接状态确认系统各组件运行正常
- 结合 Output Channel 日志获取更详细的报错信息

### 技巧

- 调试时优先看 **Agent 循环视图**（宏观流程），再看**消息检查器**（微观数据）
- 如果工具返回超时，检查 Chrome 端的 Content Script 是否正常运行
- 连接 MCP 后，MCP 工具也会出现在连接状态视图中，方便确认工具可用性

## 案例 5：多会话工作流 — 并行管理多个任务上下文

### 场景描述

你同时在做三件事：(1) 调研竞品 A 的功能，(2) 查阅技术文档编写代码方案，(3) 分析用户反馈数据。你希望在 Browser Agent 中为每个任务维护独立的对话上下文，随时切换而不丢失进度。

### 前置条件

- VSCode 插件已启动，Chrome 插件已连接
- Side Panel 已打开

### 操作步骤

1. **创建第一个会话：竞品调研** — Side Panel 默认已有一个空白会话，直接输入：
   ```
   帮我分析这个页面的产品功能布局
   ```
   会话标题会自动生成为"帮我分析这个页面的产品功能布局"的前 20 个字符。

2. **创建第二个会话：技术方案** — 使用以下任一方式创建新会话：

   - 点击 Side Panel 右上角的 **+** 按钮
   - 在输入框中输入 `/new`
   - 按 `Cmd+Shift+O`（Mac）/ `Ctrl+Shift+O`（Windows）

   切换到技术文档页面，然后输入：
   ```
   帮我解读这个 API 文档，总结关键接口和参数
   ```

3. **创建第三个会话：数据分析** — 再次创建新会话（`/new` 或 **+** 按钮），打开数据看板页面，输入：
   ```
   根据页面上的数据图表，帮我总结用户反馈的主要趋势
   ```

4. **在会话之间切换** — 点击 Side Panel 左上角的 **菜单按钮**（☰），打开会话列表侧边栏：

   ```
   ┌─────────────────────────────┐
   │  + 新建会话                  │
   ├─────────────────────────────┤
   │ 📝 根据页面上的数据图表，帮...  │ ← 当前（蓝色高亮）
   │    刚刚 · 2 条消息            │
   ├─────────────────────────────┤
   │ 📝 帮我解读这个 API 文档，...   │
   │    5 分钟前 · 4 条消息         │
   ├─────────────────────────────┤
   │ 📝 帮我分析这个页面的产品功...   │
   │    10 分钟前 · 6 条消息        │
   └─────────────────────────────┘
   ```

   点击目标会话即可切换，侧边栏自动关闭，历史消息完整加载。

5. **在不同任务间快速流转** — 切换到"竞品调研"会话，继续追问：
   ```
   和之前分析的内容比较，这个功能有什么创新点？
   ```
   AI 保留了之前的对话上下文，能准确理解"之前分析的内容"。

6. **清除不需要的会话** — 对于已完成的任务，在会话列表中：
   - **桌面端**：鼠标悬停在会话条目上，点击右侧的**删除图标** 🗑
   - **移动端**：向左滑动会话条目超过 60px，出现删除按钮

7. **利用斜杠命令快速操作** — 在任意会话中：
   - `/clear` — 清除当前会话的全部消息内容，保留会话本身
   - `/new` — 快速创建一个新会话
   - `/models` — 为不同任务选择不同的模型（如竞品分析用 GPT-4o，技术文档用 Claude 3.5 Sonnet）

### 工作流示意

```
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  会话 1：竞品调研  │    │  会话 2：技术方案  │    │  会话 3：数据分析  │
│                  │    │                  │    │                  │
│  📄 竞品官网      │    │  📄 API 文档      │    │  📄 数据看板      │
│  ↓               │    │  ↓               │    │  ↓               │
│  🔍 分析功能布局  │    │  📝 解读 API 接口  │    │  📊 总结数据趋势  │
│  ↓               │    │  ↓               │    │  ↓               │
│  💡 找到创新点    │    │  💻 输出代码方案   │    │  📈 生成分析报告  │
│  ↓               │    │  ↓               │    │                  │
│  📝 生成调研报告  │    │  ✅ 方案确认      │    │                  │
└──────────────────┘    └──────────────────┘    └──────────────────┘
        ↕ 随时切换 ↕             ↕ 随时切换 ↕
```

### 预期结果

- 每个会话独立维护上下文，切换时不丢失聊天记录
- 会话数据通过 Chrome Storage API 持久化，关闭浏览器后重新打开仍然保留
- 会话列表按更新时间排序，最近活跃的会话排在最前面
- 会话标题自动生成，可在列表中快速识别

### 技巧

- 为不同任务使用不同的模型：在切换会话后，通过模型下拉框或 `/models` 命令切换
- 会话数据存储在本地，不会上传到任何外部服务器
- 使用 `Cmd+L`（Mac）/ `Ctrl+L`（Windows）可快速清除当前会话，相当于 `/clear`

| 浏览器自动操作 | Agent ReAct 循环 + 浏览器工具 | 批量操作、表单填写、数据抓取 |
| 深度报告 | 结构化内容生成 | 竞品分析、页面评估、内容整理 |
| 调试排查 | 调试视图 + 消息检查 | 系统问题定位、Agent 行为分析 |
| 多会话工作流 | 多会话管理 + 持久化 | 并行任务、长期项目、上下文隔离 |

> 💡 这些场景可以自由组合：比如在"竞品调研"会话中让 Agent 自动操作页面抓取数据，然后生成深度报告，遇到问题时切换到 VSCode 调试视图排查。
